# pair-wise-yf-58 功能开关与受控发布控制台

## 源提示词摘要
值班员交接时说不清线上哪一版在生效，规则和放量改过几轮，定时到点又会自动切换，紧急停止有时还和切换撞在一起。需要把功能开关、发布计划、依赖开关和审计记录接成一条受控发布线：每次提交生成带版本号的候选发布，审批只认可这一次提交的内容；到点后先核对依赖开关仍然启用、审批没有因为后续改动而失效，两项都满足才一次性切到新规则和放量比例并记下生效时间；切换失败后恢复到原来正在生效的版本，这次发布留成待处理；页面要能分清正在生效、等待生效和已经作废的版本。

## 技术栈
Vue 3 + TypeScript + Vite + Ant Design Vue + Pinia + Vue Router + Axios + VueUse + VeeValidate + Zod + Vue I18n。

## 受控发布线规则
- **草稿与提交分离**：规则、放量、依赖开关只改草稿；点击「提交候选发布」才生成不可变快照。
- **版本号 + 提交哈希**：每个候选发布自动递增语义化版本（v1.0.0 → v1.1.0 → …），并绑定 7 位提交哈希；审批记录绑定同一哈希，只认可这一次提交的内容。
- **后续改动作废旧候选**：新提交会把所有「等待生效」的旧候选置为「已经作废」，旧审批随之失效。
- **生效前两项核对**：定时到点或手动生效前，逐项核对 ① 依赖开关仍启用（不存在 / 已关闭 / 紧急停止都不通过）② 产品、研发审批齐全且绑定的提交哈希未失效。
- **一次性切换 + 失败回滚**：核对通过才原子切换（原生效版本作废 → 新版本生效并记录生效时间）；任一不通过则保持原生效版本不变，本次发布留为「等待生效」并记录失败原因，审计可查。
- **紧急停止不与切换相撞**：停止后定时切换一律暂停（到点不执行），恢复后按计划继续；另有回滚上一版本能力。
- **三色版本区分**：绿色 = 正在生效、金色 = 等待生效、灰色 = 已经作废（被后续提交取代 / 回滚作废）。
- **审计记录**：提交、审批、定时、生效、失败、停止、回滚全程留痕。
- 规则命中模拟始终按「正在生效」版本的快照计算。
